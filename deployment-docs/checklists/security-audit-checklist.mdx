## Overview

This checklist provides a systematic approach to auditing the security posture of your Galileo Platform deployment. Use this regularly to ensure compliance with security best practices and regulatory requirements.

<Warning>
  **Critical:** Perform security audits quarterly and after any significant
  infrastructure changes. Document all findings and remediation actions.
</Warning>

## Pre-Audit Preparation

### Audit Scope Definition

<Card title="Audit Planning" icon="clipboard-check">

  Define systems, services, and boundaries to audit - [ ] **Audit Timeline:**
  Schedule audit windows to minimize disruption - [ ] **Audit Team:** Assign
  roles (lead auditor, technical specialists) - [ ] **Compliance Requirements:**
  Identify applicable regulations (SOC 2, GDPR, HIPAA) - [ ] **Previous
  Findings:** Review previous audit reports and remediation status - [ ]
  **Stakeholder Notification:** Inform relevant teams of audit schedule

## Infrastructure Security Audit

### Kubernetes Cluster Security

<Steps>
  <Step title="RBAC Configuration Audit">
    Review Role-Based Access Control settings:
    
    ```bash
    # List all cluster roles
    kubectl get clusterroles -o wide
    
    # Check for overly permissive roles
    kubectl get clusterrolebindings -o json | jq '.items[] | select(.roleRef.name=="cluster-admin")'
    
    # Audit service account permissions
    kubectl get serviceaccounts --all-namespaces
    ```
    
    **RBAC Audit Checklist:**
    - [ ] No default service accounts with cluster-admin privileges
    - [ ] All service accounts follow principle of least privilege
    - [ ] No wildcard permissions in production roles
    - [ ] Service accounts are namespace-scoped where possible
    - [ ] Regular review of role bindings (quarterly)
    - [ ] Unused service accounts are removed
    - [ ] Third-party service accounts properly scoped
  </Step>

  <Step title="API Server Security">
    Audit Kubernetes API server configuration:
    
    ```bash
    # Check API server flags
    kubectl -n kube-system get pod <api-server-pod> -o yaml | grep -A 20 "command:"
    
    # Verify anonymous auth is disabled
    kubectl get --raw /healthz
    ```
    
    **API Server Checklist:**
    - [ ] Anonymous authentication disabled (--anonymous-auth=false)
    - [ ] Basic authentication disabled
    - [ ] Token authentication configured with strong tokens
    - [ ] Audit logging enabled and properly configured
    - [ ] Admission controllers properly configured
    - [ ] API rate limiting enabled
    - [ ] TLS certificates are valid and not expiring soon (>30 days)
    - [ ] Insecure port (8080) is disabled
  </Step>

{" "}

<Step title="etcd Security">
  Verify etcd cluster security: **etcd Security Checklist:** - [ ] etcd
  encrypted at rest - [ ] TLS enabled for client connections - [ ] TLS enabled
  for peer connections - [ ] Root user disabled for etcd - [ ] Regular backups
  configured and tested - [ ] Access restricted to API server only - [ ]
  Firewall rules limit etcd port access
</Step>

  <Step title="Node Security">
    Audit worker node security configuration:
    
    ```bash
    # Check kubelet configuration
    kubectl get nodes -o jsonpath='{range .items[*]}{.metadata.name}{"\t"}{.status.nodeInfo.kubeletVersion}{"\n"}{end}'
    
    # Verify node restrictions
    kubectl get psp
    ```
    
    **Node Security Checklist:**
    - [ ] Nodes running latest stable Kubernetes version
    - [ ] Auto-update enabled for security patches
    - [ ] Kubelet anonymous authentication disabled
    - [ ] Kubelet authorization mode set to Webhook
    - [ ] Kubelet read-only port disabled (--read-only-port=0)
    - [ ] Pod Security Standards enforced
    - [ ] Host filesystem access restricted
    - [ ] Host network access restricted
    - [ ] Privileged containers disallowed in production
  </Step>
</Steps>

### Container Security

<Card title="Container Image Security" icon="box">
  Audit container images and registries: - [ ] **Image Scanning:** All images
  scanned for vulnerabilities - [ ] **Vulnerability Threshold:** No HIGH or
  CRITICAL vulnerabilities in production - [ ] **Image Signing:** Images signed
  and signatures verified - [ ] **Registry Access:** Strong authentication for
  image registry - [ ] **Private Registry:** Using private registry for
  proprietary images - [ ] **Base Images:** Using minimal, hardened base images
  - [ ] **Image Updates:** Regular updates for base images and dependencies - [
  ] **Image Provenance:** Track image source and build pipeline
</Card>

```bash
# Scan images with Trivy
kubectl get pods --all-namespaces -o jsonpath='{range .items[*]}{.spec.containers[*].image}{"\n"}{end}' | sort -u | while read image; do
  echo "Scanning $image"
  trivy image "$image" --severity HIGH,CRITICAL
done

# Check for unsigned images
kubectl get pods --all-namespaces -o json | jq -r '.items[] | select(.spec.containers[].image | test(".*@sha256:.*") | not) | .metadata.name'
```

### Secrets Management

<Steps>
  <Step title="Kubernetes Secrets Audit">
    Review secrets storage and access:
    
    ```bash
    # List all secrets
    kubectl get secrets --all-namespaces
    
    # Check secrets encryption
    kubectl get secrets -n galileo -o json | jq -r '.items[].metadata.name'
    
    # Verify secret references
    kubectl get pods --all-namespaces -o json | jq '.items[] | select(.spec.volumes[]?.secret != null)'
    ```
    
    **Secrets Security Checklist:**
    - [ ] Secrets encrypted at rest in etcd
    - [ ] External secrets management (Vault, AWS Secrets Manager) integrated
    - [ ] No secrets in environment variables (use volumes or external systems)
    - [ ] Secrets have proper RBAC restrictions
    - [ ] Secrets rotated regularly (quarterly minimum)
    - [ ] No hardcoded secrets in configuration files
    - [ ] Secrets not logged or exposed in error messages
    - [ ] Service account tokens auto-rotated
  </Step>

  <Step title="Certificate Management">
    Audit TLS certificates and PKI:
    
    ```bash
    # Check certificate expiration
    kubectl get certificates --all-namespaces
    
    # Verify cert-manager configuration
    kubectl get issuers,clusterissuers --all-namespaces
    ```
    
    **Certificate Checklist:**
    - [ ] All certificates valid and not expiring soon (>30 days)
    - [ ] Automated certificate renewal configured
    - [ ] Strong cipher suites configured
    - [ ] TLS 1.2 minimum enforced (TLS 1.3 preferred)
    - [ ] Certificate revocation lists (CRL) configured
    - [ ] Proper certificate chain validation
    - [ ] No self-signed certificates in production
    - [ ] Private keys properly secured and not exposed
  </Step>
</Steps>

## Application Security Audit

### Application Configuration

<Steps>
  <Step title="Security Headers">
    Verify HTTP security headers:
    
    ```bash
    # Test security headers
    curl -I https://api.<DOMAIN>
    
    # Check for required headers
    curl -I https://api.<DOMAIN> | grep -i "strict-transport-security\|x-frame-options\|x-content-type-options\|content-security-policy"
    ```
    
    **Security Headers Checklist:**
    - [ ] Strict-Transport-Security (HSTS) enabled
    - [ ] X-Frame-Options set to DENY or SAMEORIGIN
    - [ ] X-Content-Type-Options set to nosniff
    - [ ] Content-Security-Policy configured appropriately
    - [ ] X-XSS-Protection enabled
    - [ ] Referrer-Policy configured
    - [ ] Permissions-Policy configured
    - [ ] No sensitive information in response headers
  </Step>

    - [ ] Password stored securely (external secrets manager)
    - [ ] Principle of least privilege for database users
    - [ ] Regular database user audits
    - [ ] Database logging and auditing enabled

    - [ ] Database port not exposed publicly

    - [ ] Database patches up to date

```bash
apiVersion: batch/v1
kind: Job
metadata:
  name: vulnerability-scan
spec:
  template:
    spec:
      containers:
      - name: trivy
        image: aquasec/trivy:latest
        args:
          - "image"
          - "--severity"
          - "HIGH,CRITICAL"
          - "galileo/platform:latest"
      restartPolicy: Never

# Check scan results
kubectl logs job/vulnerability-scan
```

### Remediation Plan

<Steps>
  <Step title="Prioritize Findings">
    Prioritization criteria:
    
    **Priority Matrix:**
    
    | Severity | Exploitability | Priority | Timeline |
    |----------|----------------|----------|----------|
    | Critical | Easy | P0 | Immediate (24h) |
    | Critical | Moderate | P1 | 7 days |
