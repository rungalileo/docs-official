## Performance Baselines

Before tuning, establish baseline metrics to measure improvements.

### Key Performance Indicators (KPIs)

<CardGroup cols={3}>
  <Card title="Response Time" icon="clock">
    - API response: < 200ms (p95)
    - UI page load: < 2s
    - Query execution: < 500ms
  </Card>
  <Card title="Throughput" icon="gauge-high">
    - API requests/sec: varies by tier
    - Concurrent users: varies by tier
    - Data ingestion rate: GB/hour
  </Card>
  <Card title="Resource Utilization" icon="server">
    - CPU usage: 60-70% average
    - Memory usage: 70-80% average
    - Disk I/O: < 80% capacity
  </Card>
</CardGroup>

### Establishing Baselines

<Steps>
  <Step title="Run Load Tests">
    ```bash
    # Install k6 for load testing
    brew install k6  # macOS
    # or download from https://k6.io/

    # Create load test script
    cat > load-test.js <<'EOF'
    import http from 'k6/http';
    import { check, sleep } from 'k6';

    export const options = {
      stages: [
        { duration: '2m', target: 10 },   // Ramp up
        { duration: '5m', target: 10 },   // Stay at 10 users
        { duration: '2m', target: 50 },   // Ramp to 50 users
        { duration: '5m', target: 50 },   // Stay at 50 users
        { duration: '2m', target: 0 },    // Ramp down
      ],
      thresholds: {
        http_req_duration: ['p(95)<500'],
        http_req_failed: ['rate<0.01'],
      },
    };

    export default function () {
      const res = http.get('https://your-galileo-url.com/api/health');
      check(res, {
        'status is 200': (r) => r.status === 200,
        'response time < 500ms': (r) => r.timings.duration < 500,
      });
      sleep(1);
    }
    EOF

    # Run the test
    k6 run load-test.js
    ```

  </Step>

  <Step title="Monitor Resource Usage">
    ```bash
    # Monitor pods during load test
    kubectl top pods -n galileo --watch

    # Export metrics for analysis
    kubectl top pods -n galileo --containers > baseline-metrics.txt
    ```

  </Step>

  <Step title="Document Baseline">
    Record baseline metrics for future comparison:
    - Average response times by endpoint
    - Resource utilization under normal load
    - Database query performance
    - Cache hit rates
  </Step>
</Steps>

### Horizontal Pod Autoscaler (HPA)

<Callout type="tip" emoji="🎯">
  HPA automatically scales pods based on CPU/memory utilization or custom
  metrics.
</Callout>

```yaml
# hpa-api.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: galileo-api-hpa
  namespace: galileo
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: galileo-api
  minReplicas: 3
  maxReplicas: 10
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
    - type: Resource
      resource:
        name: memory
        target:
          type: Utilization
          averageUtilization: 75
  behavior:
    scaleDown:
      stabilizationWindowSeconds: 300
      policies:
        - type: Percent
          value: 50
          periodSeconds: 60
    scaleUp:
      stabilizationWindowSeconds: 60
      policies:
        - type: Percent
          value: 100
          periodSeconds: 30
        - type: Pods
          value: 2
          periodSeconds: 30
      selectPolicy: Max
```

Apply the HPA:

```bash
kubectl apply -f hpa-api.yaml

# Monitor HPA status
kubectl get hpa -n galileo --watch
```

    -- Identify slow queries
    SELECT 
      query,
      calls,
      total_exec_time,
      mean_exec_time,
      max_exec_time
    FROM pg_stat_statements
    ORDER BY mean_exec_time DESC
    LIMIT 20;

    -- Add missing indexes
    SELECT
      schemaname,
      tablename,
      attname,
      n_distinct,
      correlation
    FROM pg_stats

### Application-Level Caching

<Tabs>
  <Tab title="API Response Caching">
    ```python
    # Example caching strategy in application code
    from functools import lru_cache
    import redis
    import json

    # Initialize Redis client
    redis_client = redis.Redis(
        host='redis-master',
        port=6379,
        db=0,
        decode_responses=True,
        socket_connect_timeout=5,
        socket_keepalive=True
    )

    def get_cached_data(cache_key, ttl=300):
        """Get data from cache with TTL"""
        cached = redis_client.get(cache_key)
        if cached:
            return json.loads(cached)
        return None

    def set_cached_data(cache_key, data, ttl=300):
        """Set data in cache with TTL"""
        redis_client.setex(
            cache_key,
            ttl,
            json.dumps(data)
        )

    # Implement cache-aside pattern
    def get_project_metrics(project_id):
        cache_key = f"metrics:project:{project_id}"

        # Try cache first
        cached_data = get_cached_data(cache_key)
        if cached_data:
            return cached_data

        # Fetch from database
        data = fetch_metrics_from_db(project_id)

        # Store in cache
        set_cached_data(cache_key, data, ttl=600)

        return data
    ```

  </Tab>
  <Tab title="Query Result Caching">
    ```javascript
    // Node.js caching example
    const Redis = require('ioredis');

    const redis = new Redis({
      host: 'redis-master',
      port: 6379,
      retryStrategy: (times) => Math.min(times * 50, 2000),
      enableReadyCheck: true,
      maxRetriesPerRequest: 3,
    });

    // Cache expensive query results
    async function getCachedQuery(queryKey, queryFn, ttl = 300) {
      try {
        // Check cache
        const cached = await redis.get(queryKey);
        if (cached) {
          return JSON.parse(cached);
        }

        // Execute query
        const result = await queryFn();

        // Cache result
        await redis.setex(queryKey, ttl, JSON.stringify(result));

        return result;
      } catch (error) {
        console.error('Cache error:', error);
        // Fallback to query without caching
        return await queryFn();
      }
    }

    // Usage example
    app.get('/api/experiments/:id', async (req, res) => {
      const experimentId = req.params.id;
      const cacheKey = `experiment:${experimentId}`;

      const experiment = await getCachedQuery(
        cacheKey,
        () => db.experiments.findById(experimentId),
        600 // 10 minute TTL
      );

      res.json(experiment);
    });
    ```

  </Tab>
</Tabs>

### Cache Eviction Strategies

<CardGroup cols={2}>
  <Card title="LRU (Least Recently Used)" icon="clock-rotate-left">
    **Best for:** General-purpose caching - Evicts least recently accessed items
    - Good balance of hit rate and memory usage - Default recommendation
  </Card>
  <Card title="LFU (Least Frequently Used)" icon="chart-column">
    **Best for:** Hot data scenarios - Evicts least frequently accessed items -
    Better for data with varying access patterns - Use when some data is
    consistently hot
  </Card>
</CardGroup>

## Performance Testing

### Continuous Performance Testing

```bash
#!/bin/bash
# performance-test.sh

# Run baseline test
echo "Running baseline performance test..."
k6 run --out json=baseline.json load-test.js

# Extract key metrics
echo "Extracting metrics..."
jq '.metrics.http_req_duration.values' baseline.json > metrics.json

# Compare with previous baseline
if [ -f "previous-baseline.json" ]; then
  echo "Comparing with previous baseline..."
  python compare-metrics.py previous-baseline.json metrics.json
fi

# Save current baseline
cp metrics.json previous-baseline.json

echo "Performance test complete!"
```

### Regression Testing

<Callout type="warning" emoji="⚠️">
  Run performance tests before and after major changes to catch regressions
  early.
</Callout>

```yaml
# CI/CD pipeline integration (.github/workflows/performance-test.yml)
name: Performance Test

on:
  pull_request:
    branches: [main]

jobs:
  performance-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Run performance test
        run: |
          k6 run --out json=results.json load-test.js

      - name: Check thresholds
        run: |
          if grep -q '"thresholds_failed":true' results.json; then
            echo "Performance regression detected!"
            exit 1
          fi

      - name: Upload results
        uses: actions/upload-artifact@v3
        with:
          name: performance-results
          path: results.json
```

## Common Performance Issues and Solutions

<AccordionGroup>
  <Accordion title="Slow API Response Times">
    **Symptoms:**
    - High p95/p99 response times
    - Timeout errors
    - User complaints about sluggishness

    **Solutions:**
    1. Add missing database indexes
    2. Implement response caching
    3. Optimize N+1 queries
    4. Increase API pod replicas
    5. Add connection pooling
    6. Profile and optimize slow endpoints

  </Accordion>

  <Accordion title="High Database CPU Usage">
    **Symptoms:**
    - Database CPU constantly >80%
    - Slow query execution
    - Connection timeouts

    **Solutions:**
    1. Optimize expensive queries
    2. Add appropriate indexes
    3. Increase database resources
    4. Implement read replicas
    5. Use connection pooling
    6. Archive old data

  </Accordion>

  <Accordion title="Memory Leaks">
    **Symptoms:**
    - Gradually increasing memory usage
    - OOMKilled pods
    - Frequent pod restarts

    **Solutions:**
    1. Profile application memory usage
    2. Fix connection leaks
    3. Clear unused caches
    4. Implement proper resource cleanup
    5. Adjust memory limits
    6. Use memory profiling tools

  </Accordion>

  <Accordion title="Disk I/O Bottlenecks">
    **Symptoms:**
    - High disk latency
    - Slow database queries
    - Storage performance issues

    **Solutions:**
    1. Upgrade to faster storage (e.g., gp3, SSD)
    2. Increase IOPS allocation
    3. Optimize database writes
    4. Implement write batching
    5. Use separate volumes for logs
    6. Enable disk caching

  </Accordion>
</AccordionGroup>
