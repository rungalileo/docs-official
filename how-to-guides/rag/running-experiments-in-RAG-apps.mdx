## Overview
This guide explains how to run experiments with RAG applications to systematically evaluate and improve their performance. RAG systems combine document retrieval with language model generation, making them complex to evaluate and optimize. Galileo's experimentation framework provides the tools you need to test different components of your RAG pipeline and measure their impact on overall system performance.

Experiments are particularly valuable for RAG applications because they allow you to:
- Test different retrieval strategies and parameters
- Evaluate prompt variations for better context utilization
- Compare different embedding models and vector databases
- Measure the impact of reranking and filtering techniques
- Validate improvements across consistent datasets

## Before you start

Before you run experiments with your RAG application, ensure you have:

* A working RAG application (we'll be using the [multi-agents example](/getting-started/sample-projects/multi-agent) from the [getting started](/getting-started/how-to-use-galileo) guide)
* A free Galileo account + API credentials ([create one here](https://galileo.ai/sign-up))
* A dataset of test queries that represent your use case
* Access to the LLM integration you want to test with
* Understanding of the key metrics you want to evaluate

## Setting up your RAG experiment environment

The first step in running RAG experiments is setting up your environment and preparing your application for experimentation.

For the sake of getting started, we'll first start by cloning the FSI Chatbot example, available in our [SDK examples repository](https://github.com/rungalileo/sdk-examples).

If you have a working RAG application, feel free to start there, however, the following steps will be based off of the FSI example provided.

This How-to guide assumes you've already got the app up and running following the setup instructions, and jumps right into the experimentation process.

<Step title="Running the app as an experiment">

Experiments allow you to take a known set of inputs and evaluate different prompts, LLMs, or versions of your apps. This sample project has a unit test that runs the chatbot against a pre-defined dataset, containing a mixture of sensible and irrelevant questions.

A well-designed dataset is crucial for meaningful RAG experiments. Your dataset should represent the types of queries your system will encounter in production.


<Step title="Compare experiment results">
Navigate to your Galileo console and compare the results of different experiments:

1. Go to the **Experiments** section in your project
2. Select multiple experiments to compare
3. Review the metrics across different configurations
4. Look for patterns in performance improvements

Key metrics to focus on for the multi-agent banking chatbot:

- **Correctness**: How accurate are the responses?
- **Completeness**: How much of the relevant information is included?
- **Action Advancement**: How well does the supervisor agent route queries to the right specialist agents?
- **Action Completion**: How successfully do the specialist agents complete their tasks?

For RAG-specific components:
- **Chunk Attribution**: How well does the credit card information agent use retrieved documents?
- **Chunk Relevance**: How relevant are the retrieved credit card documents?
</Step>

<Step title="Identify improvement opportunities">

Based on your experiment results, identify areas for improvement:

- **Low action advancement**: The supervisor agent may not be routing queries correctly
- **Low action completion**: Specialist agents may not be completing their tasks properly
- **Low chunk attribution**: The RAG agent may not be using retrieved context effectively
- **Low chunk relevance**: The retrieval system may need tuning for credit card information
- **Low completeness**: Responses may be missing important information
- **Low correctness**: Information may be inaccurate or incomplete

</Step>
