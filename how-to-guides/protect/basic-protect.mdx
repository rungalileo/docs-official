## Overview

This guide explains how to add runtime protection to a simple chatbot.

<Note>
Runtime protection requires either:

- [**Luna‑2**](/concepts/luna/luna), available on Galileo enterprise plans, **or**
- custom code‑based metrics that you would implement yourself.

Because runtime guardrails must evaluate inputs in real time, they depend on a model designed for **fast evaluations**.

⚠️ This guide focuses on the **first option** (using Luna‑2).  
Please ensure your account has access to Luna‑2 **before following this guide**.  

If you’d like access to Luna‑2 for enterprise runtime protection, please [contact us](https://galileo.ai/contact-sales).
</Note>

You will be running a basic chatbot, detecting toxicity in the users input, and if this is detected, ending the conversation. You will start by creating a central stage, as if you were an AI governance team. You will then use this stage in a simple chatbot.

In a real-world scenario, you could use this detection to redirect a user from an AI chatbot to a human representative.

In this guide you will:

1. [Set up a project with Galileo](#install-dependencies)
1. [Create a central stage](#create-a-central-stage)
1. [Create a basic chatbot](#create-a-basic-chatbot)
1. [Add runtime protection to your basic chatbot](#add-runtime-protection-to-your-basic-chatbot)

### 🔧 Troubleshooting Scorer & Stage Issues

- **Stage not found**  
  Error:  
  ```text
  Stage 'Toxicity Stage' not found
  ```  
  **Fix:** run `create_central_stage.py` in the same project.

- **Scorer evaluation failures (`FAILED` / `ERROR`)**  
  Symptoms: rules always `FAILED`, metrics `null`, or errors like:  
  ```text
  error_message: "[Errno -2] Name or service not known"
  Protect status: ExecutionStatus.failed / ExecutionStatus.error
  ```  
  Example JSON:  
  ```json
  "rule_results":[{"metric":"input_toxicity","value":null,"status":"FAILED"}]
  ```  
  **Cause/Fix:** Usually wrong console URL. SaaS console (`https://app.galileo.ai`) lacks runtime protection scorers; use **enterprise console** (`https://console.galileo.yourcompany.com`). Unsupported scorers (e.g. `toxicity_gpt`) will error—use `input_toxicity`, `input_pii`, or `prompt_injection`. To see available scorers:  
  ```python
  from galileo import GalileoScorers
  print(list(GalileoScorers.__members__.keys()))
  ```  
  Also confirm enterprise console has Luna models provisioned.

- **Guardrail not triggering as expected**  
  Default toxicity rule threshold = `0.01`.  
  Neutral `"hello there"` → `NOT_TRIGGERED` (≈3.2e‑05 < 0.01)  
  Toxic `"you are stupid"` → `TRIGGERED` (≈0.99 > 0.01)  
  **Fix:** tune sensitivity via `target_value` in your `Rule`.
</Note>

Whenever your chatbot input **passes the guardrail** and is sent to the LLM, a **trace** is logged in your Galileo project.
