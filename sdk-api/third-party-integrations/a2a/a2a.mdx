The `galileo-a2a` package provides automatic OpenTelemetry instrumentation for the [Google A2A (Agent-to-Agent)](https://github.com/google/A2A) protocol. It traces all client and server interactions across agent boundaries, giving you end-to-end distributed tracing of multi-agent systems in Galileo.

## Installation

```bash
pip install galileo-a2a
```

<Note>
**Requirements:** Python 3.10+, `a2a-sdk >= 0.3.0`, and a [Galileo API key](https://app.galileo.ai/settings/api-keys).
</Note>

## How it works

`galileo-a2a` uses OpenTelemetry auto-instrumentation to monkey-patch the `a2a-sdk`. When you call `instrument()`, it wraps both client and server methods to create spans and propagate trace context automatically.

### Cross-agent trace correlation

When a client agent sends a message to a server agent, `galileo-a2a` injects trace context into the A2A request metadata. The server-side instrumentation extracts this context and creates child spans under the same trace, giving you a single distributed trace across all agents.

This means you can see the full request flow — from the orchestrator's decision to delegate, through the A2A network call, to the downstream agent's execution — all in one trace in Galileo.

### Session tracking

A2A uses `context_id` to group related messages into conversations. `galileo-a2a` maps `context_id` to `session.id` in OpenTelemetry, so all interactions within the same conversation are grouped into a Galileo session automatically.

### Task state tracking

A2A tasks go through lifecycle states (`submitted`, `working`, `completed`, `failed`, `canceled`, `rejected`). `galileo-a2a` captures these transitions as span attributes:

- `a2a.task.state` — the final task state
- `a2a.task.id` — the task identifier
- Error states (`failed`, `rejected`, `canceled`) automatically mark the span as `ERROR`
- Completed tasks set `gen_ai.response.finish_reasons` to `"stop"`

## Configuration

`A2AInstrumentor.instrument()` accepts the following parameters:

| Parameter | Type | Description |
|-----------|------|-------------|
| `tracer_provider` | `TracerProvider` | The OTel tracer provider to use for creating spans. Must have the `GalileoSpanProcessor` registered. |
| `agent_name` | `str` (optional) | A human-readable name for this agent. Appears as `gen_ai.agent.name` in span attributes. |

Environment variables for Galileo configuration:

| Variable | Description |
|----------|-------------|
| `GALILEO_API_KEY` | Your [Galileo API key](https://app.galileo.ai/settings/api-keys) |
| `GALILEO_PROJECT` | The Galileo project to log traces to |
| `GALILEO_LOG_STREAM` | The Log stream within the project |

## Span attributes

All spans created by `galileo-a2a` include these attributes:

{/*<!-- markdownlint-disable MD013 -->*/}

| Attribute | Description |
|-----------|-------------|
| `gen_ai.operation.name` | The operation type (`invoke_agent` for client, `process_agent_request` for server) |
| `gen_ai.system` | Always `"a2a"` |
| `gen_ai.agent.name` | The agent name (if provided to `instrument()`) |
| `gen_ai.input.messages` | JSON-encoded input message text |
| `gen_ai.output.messages` | JSON-encoded output message text |
| `gen_ai.response.finish_reasons` | Finish reason based on task state |
| `a2a.rpc.method` | The A2A RPC method (`SendMessage`, `GetTask`, etc.) |
| `a2a.task.id` | The A2A task identifier |
| `a2a.task.state` | The final task state (`completed`, `failed`, etc.) |
| `a2a.context_id` / `session.id` | The conversation context ID |

{/*<!-- markdownlint-enable MD013 -->*/}

## AGNTCY compatibility

`galileo-a2a` is compatible with the [AGNTCY Observe SDK](https://docs.agntcy.org/pages/agntcy/observe-sdk/). If an incoming request uses the AGNTCY `observe` metadata key instead of `galileo_observe`, the instrumentor will extract trace context from it. Galileo's key takes precedence when both are present.

## Cleanup

To remove instrumentation at shutdown:

```python
instrumentor.uninstrument()
tracer_provider.shutdown()
```
