---
title: "Register a metric"
description: "Publish a fine-tuned metric to the Galileo metrics store."
---

Once a run reaches **Fine-tuned**, you can register the resulting metric. Registration publishes the metric to the [Galileo metrics store](/concepts/metrics/overview), where it becomes available across the Galileo platform — for evaluation in projects, observability dashboards, and runtime guardrails.

<Frame caption="Register metric modal opened from the run details page">
  ![Register metric modal](/images/luna-studio/metrics/register-metric.png)
</Frame>

## Prerequisites

- The run must be in the **Fine-tuned** status. See [Run lifecycle](/luna-studio/runs/lifecycle).
- Your org must have an active [Galileo integration](/luna-studio/integrations/galileo).

## Where you can register from

The **Register metric** action appears in three places:

- **Run details page** &mdash; primary footer button on Fine-tuned runs. See [Run details](/luna-studio/runs/run-details#footer).
- **Training runs table** &mdash; an action link on each Fine-tuned row. See [Training runs home](/luna-studio/projects/training-runs-home#runs-table).
- **Metrics page** &mdash; an action link on each Fine-tuned metric. See [Metrics overview](/luna-studio/metrics/overview).

All three open the same **Register metric** modal.

## The modal

The modal title is **Register metric** with the subtitle "Your metric will appear in Galileo metrics store."

| Field       | Notes                                                                 |
| ----------- | --------------------------------------------------------------------- |
| Metric name | The name the metric will have in the Galileo metrics store. Required. |

The primary button is **Register**.

## Steps

<Steps>
  <Step title="Click Register metric">
    From the run details footer, the runs table row, or the metrics page row.
  </Step>

<Step title="Enter a metric name">
  Use a name that's clear in the Galileo metrics store, where it'll sit alongside built-in metrics.
  Examples: `support-tone-strict`, `pii-detector-en`.
</Step>

  <Step title="Click Register">
    The modal closes. The run's status flips to **Registered** and the **Register metric** affordance disappears for that run.
  </Step>
</Steps>

## What registration does

Registration:

1. Snapshots the fine-tuned model.
2. Creates a metric definition in the [Galileo metrics store](/concepts/metrics/overview) using the name you entered.
3. Records the original Luna Studio run as the metric's source.

The registered metric is a fine-tuned [Luna-2](/concepts/luna/luna) model that runs alongside Galileo's other Luna-based evaluators — same low-latency SLM infrastructure, your custom-trained weights.

After registration, the metric is usable from anywhere in Galileo:

- As an evaluation metric on Galileo projects.
- As an observability metric on traces.
- As a guardrail at runtime.

See the [Galileo docs](/what-is-galileo) for usage from the rest of the platform.

## Naming guidance

- Use lowercase with hyphens: `customer-tone-classifier`, not `Customer Tone Classifier`.
- Include the language or domain if relevant: `pii-detector-en`, `legal-toxicity`.
- Avoid version suffixes (`-v1`, `-v2`) unless you'll register multiple variants — the run history already captures versions in Luna Studio.

<Warning>
  Metric names should be unique within your Galileo workspace. If a metric with the same name
  already exists, registration fails with a duplicate-name error. Pick a different name and try
  again.
</Warning>

## Unregister?

There's no **unregister** flow inside Luna Studio. To remove a registered metric, delete it from the [Galileo metrics store](/concepts/metrics/overview). The Luna Studio run remains in **Registered** status — it's a record of what was published.
