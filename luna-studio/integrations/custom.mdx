The **Custom** integration lets you describe arbitrary models with a JSON config. Use it for in-house deployments, OpenAI-compatible proxies, or models that aren't covered by the [standard providers](/luna-studio/integrations/llm-providers).

<Frame caption="Custom integration modal">
  ![Custom integration modal](/images/luna-studio/integrations/custom-modal.png)
</Frame>

## How it works

The modal has a single field — a JSON code editor with auto-formatting and live lint errors. Define a `model_properties` array; each entry describes one model the integration exposes.

The default content the editor seeds for you looks like:

```json
{
  "model_properties": [
    {
      "name": "gpt-5.2",
      "endpoint": "https://my-proxy.example.com/v1/chat/completions",
      "type": "openai-compatible",
      "headers": {
        "Authorization": "Bearer YOUR_TOKEN_HERE"
      }
    },
    {
      "name": "gpt-5.4",
      "endpoint": "https://my-proxy.example.com/v1/chat/completions",
      "type": "openai-compatible",
      "headers": {
        "Authorization": "Bearer YOUR_TOKEN_HERE"
      }
    },
    {
      "name": "claude-opus-4-6",
      "endpoint": "https://my-proxy.example.com/v1/messages",
      "type": "anthropic-compatible",
      "headers": {
        "x-api-key": "YOUR_KEY_HERE"
      }
    }
  ]
}
```

<Note>
  The fields above are illustrative — see the link inside the modal labelled "View JSON examples"
  for the canonical schema reference, since the supported keys evolve as new model families ship.
</Note>

## Add a custom integration

<Steps>
<Step title="Open the Custom card">
  From the [Integrations](/luna-studio/integrations/overview) page, scroll to the bottom of the LLM Integration section and click **Add integration** on the **Custom** card.
</Step>

<Step title="Edit the JSON">
Replace the sample `model_properties` with entries for your own models. Keys you'll typically use:

- `name` — the display label that appears throughout Luna Studio (e.g. in the Generate drawer's model select).
- `endpoint` — the URL Luna Studio POSTs to.
- `type` — the wire format (e.g. `openai-compatible`, `anthropic-compatible`).
- `headers` — request headers, including auth.

</Step>

<Step title="Validate">
The editor lints as you type. JSON errors show inline and disable the **Save changes** button
until they're fixed.
</Step>

<Step title="Click Save changes">
  The card flips to **Active**.
</Step>
</Steps>

## When to use Custom vs other integrations

| Use case                                                     | Pick                                                                         |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| OpenAI directly                                              | [OpenAI](/luna-studio/integrations/llm-providers#openai)                                 |
| Self-hosted OpenAI-compatible proxy                          | Custom                                                                       |
| In-house Llama deployment                                    | Custom (or [SageMaker](/luna-studio/integrations/aws-bedrock-sagemaker) if hosted there) |
| Mix of OpenAI + a private fine-tune behind a single endpoint | Custom                                                                       |
| You need to set custom headers (e.g. for a corporate proxy)  | Custom                                                                       |

<Tip>
  Most teams start with one of the named providers and only switch to Custom when they hit a
  specific need (corporate proxy, internal model, OpenAI-compatible third party). The named
  providers handle auth and request formatting for you.
</Tip>

## Validation errors

| Error                               | Fix                                                                                                    |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **Unexpected token …**              | JSON syntax error. Check for trailing commas or smart quotes.                                          |
| **Required field missing**          | Add the missing key shown in the lint marker.                                                          |
| **Save changes** button is disabled | Either a required field is blank or JSON has a syntax error. The editor highlights the offending line. |

## Update or remove

- **Update** &mdash; reopens the editor pre-filled. Saving overwrites the previous JSON.
- **Remove** &mdash; opens a confirmation dialog. Removing deletes the credentials. Active runs continue with the credentials they captured at launch.
