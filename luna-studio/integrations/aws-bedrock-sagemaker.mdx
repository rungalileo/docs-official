AWS Bedrock and AWS SageMaker share a richer integration modal than the standard providers. Both support two authentication modes (Access Key and Assumed Role), and SageMaker additionally requires per-model schema configuration.

## Authentication

Both Bedrock and SageMaker integrations use the same authentication tabs at the top of the modal.

<Tabs>
  <Tab title="Access Key">
    Use long-lived AWS credentials. Best for shared service accounts that don't roll their keys.

    | Field             | Notes                                                                       |
    | ----------------- | --------------------------------------------------------------------------- |
    | AWS Access Key    | The IAM access key ID.                                                      |
    | AWS Access Secret | The IAM secret access key. Stored as a password field.                      |
    | Region            | AWS region, e.g. `us-west-2`. Defaults to `us-west-2`.                       |

  </Tab>
  <Tab title="Assumed Roles">
    Use IAM role assumption with no long-lived credentials. Best when Luna Studio runs in your AWS account or has cross-account trust set up.

    | Field    | Notes                                                                       |
    | -------- | --------------------------------------------------------------------------- |
    | Role ARN | The full ARN of the role Luna Studio assumes, e.g. `arn:aws:iam::123:role/...`. |
    | Region   | AWS region, e.g. `us-west-2`. Defaults to `us-west-2`.                       |

  </Tab>
</Tabs>

## Bedrock

Bedrock integrations stop at authentication — once Luna Studio has valid AWS credentials and a region, it discovers the available foundation models on its own.

<Steps>
  <Step title="Open the AWS Bedrock card">
    From the [Integrations](/luna-studio/integrations/overview) page.
  </Step>
  <Step title="Pick an authentication tab">Access Key or Assumed Roles.</Step>
  <Step title="Fill in the fields">See the table above.</Step>
  <Step title="Click **Save changes**">The card flips to **Active**.</Step>
</Steps>

## SageMaker

SageMaker integrations are model-specific — your account hosts the models on its own endpoints, so Luna Studio needs to know how to call each one. After authentication, the modal shows a **Model Configuration** section where you define up to three models.

### Model Configuration

The Model Configuration section uses tabs (one per model) with a **+** button to add another. You can have up to three models per integration today.

For each model, fill in:

| Field          | Notes                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------- |
| Model Alias    | A short name you'll reference elsewhere in Luna Studio. Must be unique across the integration's models. |
| Endpoint       | The SageMaker endpoint name or full URL.                                                                |
| Schema mapping | A sub-card describing how Luna Studio should structure requests and parse responses. See below.         |

### Schema mapping

The schema mapping sub-card lets you tell Luna Studio where the prompt goes in the request body and where to find the response text.

| Field         | Notes                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------ |
| Template      | A starter template. Today, the only option is **Huggingface**, which prefills standard mappings. |
| Prompt path   | JSONPath where the prompt is injected, e.g. `inputs`.                                            |
| Response path | JSONPath where the response text lives in the model's output, e.g. `[0].generated_text`.         |

### Advanced settings

The schema mapping has a **Show advanced settings** toggle. Expanding it reveals sampling controls:

| Field             | Notes                                       |
| ----------------- | ------------------------------------------- |
| Temperature       | Sampling temperature, e.g. `0.7`.           |
| Max Tokens        | Maximum tokens to generate.                 |
| Top K             | Limits to top-K tokens at each step.        |
| Top P             | Nucleus sampling cutoff.                    |
| Frequency Penalty | Penalty for repeating tokens.               |
| Presence Penalty  | Penalty for reusing previously seen tokens. |

Leave these blank to use SageMaker defaults.

<Tip>
  If your endpoint uses the Huggingface Text Generation Inference (TGI) format, pick the
  **Huggingface** template and skip directly to **Save changes** — the prefilled mappings are
  correct for TGI's default request/response shape.
</Tip>

## Updating an AWS integration

Click **Update** on the card to reopen the modal pre-filled. The active authentication tab is the one you used last time. Switching tabs replaces the credentials — Luna Studio doesn't keep both modes simultaneously.

## Removing an AWS integration

Click **Remove**, then **Remove** in the confirmation dialog. Bedrock and SageMaker can be removed independently — they're separate cards on the Integrations page.
