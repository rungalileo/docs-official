## Overview

In this tutorial, you'll learn how to build "Galileo's Gizmos" - a conversational AI agent that can handle ecommerce operations using Stripe's Agent Toolkit observed with Galileo's AI Reliability toolkit. This tutorial is intended for TypeScript/JavaScript developers building AI-powered commerce applications. It assumes you have basic knowledge of:

- TypeScript/JavaScript and Node.js
- Package manager of choice (we’ll be using npm)
- Code editor of choice (VS Code, Cursor, Warp, etc.)
- API keys for: 
    - [OpenAI](https://platform.openai.com/docs/overview), [Stripe](https://stripe.com/docs/api), and [Galileo (free!)](https://app.galileo.ai)

By the end of this tutorial, you'll be able to:
- Build a conversational AI agent using Stripe's Agent Toolkit
- Implement comprehensive e-commerce operations (products, customers, payments)
- Monitor agent performance and user interactions with Galileo
- Create custom metrics to evaluate commerce-specific agent quality

## Background

We'll be building "Galileo's Gizmos" - a space-themed ecommerce AI assistant that demonstrates real-world commerce automation. The agent includes multiple interaction modes:

- **CLI Mode**: Interactive command-line interface for testing
- **Web Mode**: Express.js server with REST API and web interface
- **Demo Mode**: Automated examples showcasing agent capabilities

The agent can handle:
- Product catalog management
- Customer record creation and management
- Payment link generation
- Subscription setup
- Invoice creation and management
- Real-time inventory checking

We'll demonstrate how to observe the agent’s performance, and monitor tool calls, using Galileo.

## Set up the project

<Steps>
<Step title="Clone the project in your IDE of choice.">
The starter project is in the 'sdk-examples/typescript/agent/strip-agent-tool' folder in the cloned repo.
```bash
git clone https://github.com/rungalileo/sdk-examples
cd sdk-examples/typescript/agent/stripe-agent-tool
``` 
</Step>

<Step title="Install dependencies using npm.">
The project uses npm to manage TypeScript dependencies. Install all required packages:

```bash
npm install
```

This will install all dependencies including:
- `@stripe/agent-toolkit` - Stripe's AI agent toolkit
- `@langchain/openai` - OpenAI integration for LangChain
- `langchain` - LangChain framework for building AI applications
- `express` - Web server framework
- `galileo-sdk` - Galileo monitoring and observability
- `typescript` - TypeScript compiler and tooling
</Step>

<Step title="Configure your .env file.">
Take the `.example.env` file, copy it, renaming it to `.env` and add in your own variables. Be sure the variables are added to your `.gitignore` file.

When complete, it should look something like this:
```env
# Example .env file — copy this file to .env and fill in the values. 
# Be sure to add the .env file to your .gitignore file.
  
# OpenAI API Key (required)
OPENAI_API_KEY=your-openai-api-key-here

# Stripe API Key (required)
STRIPE_SECRET_KEY=sk_test_your-stripe-secret-key-here

# Galileo Configuration (required for observability)
GALILEO_API_KEY=your-galileo-api-key-here
GALILEO_PROJECT_NAME=galileo-gizmos
GALILEO_LOG_STREAM=development

# Optional Configuration
NODE_ENV=development
PORT=3000
LOG_LEVEL=info

# Agent Configuration
AGENT_MODEL=gpt-4o-mini
AGENT_TEMPERATURE=0.1
AGENT_MAX_ITERATIONS=4
AGENT_VERBOSE=true
```

</Step>

<Step title="Run the Agent and test the application">
After your environment variables are set, you can run the application in multiple modes. The application is designed as a TypeScript/Node.js application with three different interfaces:

**Demo Mode** (Automated examples):
```bash
npm run dev
```

**Interactive CLI Mode** (command line interface):
```bash
npm run interactive
```

**Web Server Mode** (REST API + Web interface):
```bash
npm run web
```

For the web server mode, your application will be running at http://localhost:3000 — open that within your browser and start exploring.

Try different commerce operations:
- "Show me your products"
- "Create a payment link for the Space Telescope"
- "Add a customer named Neil Armstrong"
- "Set up a monthly subscription for Mars Rocks"

The standard flow of the application is as follows: 
User Input → Agent Executor → Stripe Tools → LLM Processing → Commerce Operations → Response
</Step>
</Steps>

## Create a custom LLM-as-a-Judge metric in Galileo

<Steps>
<Step title="Add metrics to your log stream in Galileo">
Navigate to your project home inside of Galileo.

Look for the name of your project, and open it up to the log stream you've got your traces in.

Click on the **Trace** view and see your most recent runs listed below, it should look something like below.

![A view of log streams within the Galileo Console](cookbooks/use-cases/stripe-ecommerce-agent/2025-07-log-stream-galileo-gizmos.webp)

From this view, navigate to the upper right hand side of your screen and click on the **Configure Metrics** button.  A side panel should appear with a set of different metrics from you to choose from. 

![An image with an arrow pointing to the **Configure Metrics** button from within the log stream interface.](/cookbooks/use-cases/custom-metric-startup-sim/2025-07-configure-metrics-button.webp)
</Step>

<Step title="Add your metrics">
Add your metrics to the application to best monitor the agent. 

After clicking on the **Configure Metrics** button you'll be presented with a screen of different metrics.  

Let's turn on a few different [agentic metrics](https://v2docs.galileo.ai/concepts/metrics/agentic/agentic-overview) to evaluate the performance of our docs.

Once in this panel, navigate to the **Create Metric** in the upper right hand corner of your screen, and select **LLM-as-a-Judge** Metric.

![A screenshot with a red arrow pointing to the Create Metric button in the upper right hand corner of the screen.](/cookbooks/use-cases/custom-metric-startup-sim/2025-07-create-metric.webp)
</Step>

<Step title="Create your own LLM-as-a-Judge prompt">
A window will appear where you will be able to generate a metric prompt. A metric prompt is a prompt to prompt the creation of the final LLM as a judge prompt. This is to ensure you spend your time focused on what's important (the success criteria) instead of worrying about the output format.

When writing a good prompt, remember that the goal is to transform **subjective evaluation criteria** into a consistent, repeatable process that a language model can assess.

Use a specific, structured metric for best results. For this e-commerce agent example, I've provided a sample custom metric below that evaluates customer service quality and commerce effectiveness:

```markdown
You are an expert e-commerce customer service evaluator specializing in AI-powered commerce agents. Your role is to evaluate the effectiveness and quality of customer service interactions generated by an AI commerce assistant.
EVALUATION CRITERIA:
For each criterion, answer TRUE if the content meets the standard, FALSE if it doesn't.
1. COMMERCE ACCURACY
   - [ ] Agent provides accurate product information
   - [ ] Pricing and availability information is correct
   - [ ] Agent checks real inventory before making recommendations
   - [ ] Payment processes are handled correctly
2. CUSTOMER SERVICE QUALITY
   - [ ] Agent responds helpfully and professionally
   - [ ] Tone is appropriate for the brand (space-themed but professional)
   - [ ] Agent addresses customer questions completely
   - [ ] Agent guides customers through processes clearly
3. TECHNICAL EXECUTION
   - [ ] Agent uses appropriate Stripe tools for the task
   - [ ] API operations are executed correctly
   - [ ] Error handling is appropriate when issues occur
   - [ ] Agent doesn't suggest non-existent products
4. CONVERSATION FLOW
   - [ ] Agent maintains context throughout the conversation
   - [ ] Responses are relevant to customer requests
   - [ ] Agent concludes conversations appropriately
   - [ ] Agent doesn't ask repetitive questions
5. BUSINESS VALUE
   - [ ] Agent successfully guides customers toward purchase
   - [ ] Agent handles objections or questions professionally
   - [ ] Agent provides clear next steps
   - [ ] Agent creates a positive customer experience
6. COMPLIANCE & SAFETY
   - [ ] Agent follows commerce best practices
   - [ ] Agent handles sensitive payment information appropriately
   - [ ] Agent provides accurate terms and conditions
   - [ ] Agent maintains appropriate professional boundaries
 Answer TRUE only if ALL of the following conditions are met:
   - [ ] At least 85% of all criteria are rated TRUE
   - [ ] No critical criteria (Commerce Accuracy, Customer Service Quality) are rated FALSE
   - [ ] Response would provide value to a real customer
   - [ ] Agent successfully completes the requested commerce operation
   - [ ] Overall interaction maintains professional standards
```

When added, press **Save** then test your metric.  The evaluation prompt will then be generated for you to see within a preview window. 
</Step>

<Step title="Test your metric">
From within the Custom Metric pane, select **Test Metric**. 

![A screenshot showing where to test the metric within the Custom Metric UI](/cookbooks/use-cases/custom-metric-startup-sim/2025-07-test-metric.webp)

Take the output from an earlier commerce interaction, and paste it in the output section of the **Test Metric** page, and check the response.

![A screenshot showing the Test Metric interface within the Custom LLM-as-judge metric interface](/cookbooks/use-cases/custom-metric-startup-sim/tested-metric.webp)

Continue tweaking the prompt until you have a metric that you feel confident with — the goal isn't to have a metric that is perfect 100% of the time, but helps you determine what "good" commerce customer service looks like.

Have examples of what an e-commerce expert would consider to be "good" and "bad" customer service interactions to test your metric for success. Good examples include:
- Successfully helping a customer find and purchase a product
- Providing accurate pricing and availability information
- Handling customer questions professionally
- Guiding customers through payment processes

Bad examples include:
- Suggesting non-existent products
- Providing incorrect pricing information
- Failing to complete commerce operations
- Unprofessional or confusing responses
</Step>

<Step title="Add your Custom Metric">
Once tested, your metric will appear in the list of available metrics.  Click on **Configure Metrics** and flip the toggle the metric you've created, on. From there, it can be used to assess future LLM outputs across runs and sessions—giving you visibility into quality over time.

![A gif showing where to add the custom metric to your application within the Custom Metric UI](/cookbooks/use-cases/custom-metric-startup-sim/adding-custom-metric.webp)
</Step>
</Steps>
