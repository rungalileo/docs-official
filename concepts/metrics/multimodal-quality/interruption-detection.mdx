<DefinitionCard>
  <strong>Interruption Detection</strong> is a session-level binary metric that identifies turn-taking violations in audio-based agent conversations — including the agent speaking over the user, the agent cutting off the user before intent
  is complete, and the user cutting off the agent.
</DefinitionCard>

Interruption Detection evaluates the full list of trace inputs and outputs in a session to determine whether any turn-taking violations occurred. It covers three interruption patterns:

- **Agent overlap**: The agent speaks while the user is still speaking
- **Premature agent barge-in**: The agent begins its response before the user's intent is complete
- **User barge-in**: The user speaks while the agent is still speaking

This is a **boolean** metric, returning a confidence score that an interruption occurred. The score ranges from 0% (no confidence an interruption occurred) to 100% (complete confidence that at least one interruption occurred).

## Inputs considered

Interruption Detection operates at the **session level** and is computed over the full list of trace inputs and outputs for that session. The evaluator examines:

- The ordered sequence of speaker turns (agent and user) across all traces in the session
- Speaker attribution signals and, where available, timing or overlap metadata embedded in trace inputs/outputs

<Note>Accuracy improves when traces include explicit speaker attribution and overlap or timestamp signals. When only turn ordering is available, the metric approximates interruption based on conversational sequencing.</Note>

## Best practices

<CardGroup cols={2}>
  <Card title="Include speaker attribution" icon="user-tag">
    Log each turn with a clear speaker label (user vs. agent) so the evaluator can correctly identify who spoke and in what order.
  </Card>
  <Card title="Log overlap and timing signals" icon="clock">
    Where your audio pipeline captures overlap events or timestamps, include them in trace metadata to improve detection accuracy.
  </Card>
  <Card title="Tune endpointing thresholds" icon="sliders">
    Use Interruption Detection scores to calibrate VAD and endpointing settings — high premature barge-in rates suggest endpointing is too aggressive.
  </Card>
  <Card title="Monitor user barge-in separately" icon="chart-line">
    Track user barge-in as a distinct signal for agent response length; high rates often indicate agent turns are too long or not relevant enough.
  </Card>
</CardGroup>
