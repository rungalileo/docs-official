<DefinitionCard>
  <strong>Visual Quality</strong> is a binary metric that judges whether the quality of an input image in an LLM span is sufficient for the task described in the adjoining text prompt to be reliably performed.
</DefinitionCard>

The Visual Quality metric is task-grounded rather than purely aesthetic: an image is considered high quality only if the specific task can be completed reliably from the visual evidence. An image is considered low quality when blur, glare, compression artifacts, darkness, occlusion, crop, distortion, or other degradation makes task-critical information unprocessable.

This is a **boolean** metric, returning a confidence score that the image quality is sufficient for the task. The score ranges from 0% (no confidence the image quality is sufficient) to 100% (complete confidence that the image quality is sufficient).

## Inputs considered

The evaluator examines the following when available:

- The raw input image provided to the LLM span
- The text prompt that defines the task the model is expected to perform on that image

Quality is evaluated strictly with respect to whether the task described in the prompt can be completed; a low-resolution image that is perfectly adequate for one task may be insufficient for another.

## What constitutes high quality (1)

- All task-relevant regions of the image are clearly visible and unobstructed
- Sharpness, brightness, contrast, and compression level are sufficient to read or interpret task-critical information
- No artifacts (glare, motion blur, heavy JPEG blocking, severe vignetting) prevent reliable interpretation

## What constitutes low quality (0)

- Blur, glare, or compression artifacts obscure information the task requires
- Darkness or overexposure makes key regions unreadable
- Occlusion or cropping removes task-critical content from the frame
- Distortion (e.g. extreme lens distortion) prevents reliable spatial interpretation

## Best practices

<CardGroup cols={2}>
  <Card title="Pair with the task prompt" icon="link">
    Always evaluate Visual Quality in the context of the specific task prompt; the same image can be high quality for one task and low quality for another.
  </Card>
  <Card title="Set a routing threshold" icon="code-branch">
    Define a minimum acceptable confidence score and route low-quality inputs to a fallback path (e.g. request a new image or skip the span).
  </Card>
  <Card title="Log quality signals" icon="chart-line">
    Capture Visual Quality scores over time to identify systematic input quality issues, such as a consistently poor camera source.
  </Card>
  <Card title="Combine with Visual Fidelity" icon="layer-group">
    Use Visual Quality on input images and Visual Fidelity on generated images to cover both ends of a multimodal pipeline.
  </Card>
</CardGroup>
