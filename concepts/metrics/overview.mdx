Galileo provides a comprehensive suite of [out-of-the-box metrics](/concepts/metrics/metric-comparison) designed to evaluate various aspects of AI system performance without requiring custom implementation. Most out-of-the-box metrics are LLM-based.

With these metrics, you can quickly spot problems, track improvements, and make your AI work better for your users. These metrics apply to different node types (such as session, trace, or different span types), depending on the metric.

You can then expand these metrics with custom metrics:

- [Decision model metrics](/concepts/metrics/custom-metrics/custom-decision-model-metrics)
- [LLM-as-a-judge metrics](/concepts/metrics/custom-metrics/custom-metrics-ui-llm)
- [Luna metrics](/concepts/luna/luna)
- [Code-based metrics](/concepts/metrics/custom-metrics/custom-metrics-ui-code)
- [Composite code-based metrics](/concepts/metrics/custom-metrics/composite-metrics)

After you set up metrics, you can use them in [experiments](/concepts/experiments/running-experiments-in-console) and [Log streams](/concepts/logging/configure-metrics/configure-metrics) to monitor AI system performance.

## Which metric should I use?

Metrics can use decision models, LLMs, Luna small language models (SLMs), or code to evaluate inputs and outputs.

Choose a metric type depending on the reasoning and specialization you need:

| Metric type | Use this for |
| --- | --- |
| Decision model metric | Fast and cost-efficient structured judgments on large volumes of text, such as classifications and scoring. |
| LLM-as-a-judge metric | Evaluations that require nuanced or multi-step reasoning, explanations, counts, percentages, images, audio, files, or very long inputs. LLMs are also useful if you're developing a metric or frequently changing its rubric. |
| Luna metric | Task-based AI evaluations. Use Luna models for out-of-the-box metrics, task-specific fine-tuning, multimodal inputs, or private deployments. |
| Code-based metric | Deterministic rules; repeatable checks with explicitly defined logic. |
| Composite code-based metric | Advanced use cases, when you want to access and leverage the results of other metrics to perform sophisticated evaluations. |

The following table describes the differences between decision model and LLM-as-a-judge metrics:

| Capability | Decision model metric | LLM-as-a-judge metric |
| --- | --- | --- |
| What you write | One question and its allowed answers | A prompt and scoring criteria |
| Explanation | None | Available when reasoning is enabled |
| Number of judges | No judge-count setting | Configurable |
| Input | Text only | Text and supported multimodal inputs |
| Output types | Boolean, categorical, discrete | Boolean, categorical, count, discrete, percentage |
| Support for batch mode | Yes | No |

## How do I use metrics effectively?

To get the most value from Galileo metrics:

1. **Start with key metrics**: Focus on metrics most relevant to your use case.
2. **Establish baselines**: Understand your current performance before making changes.
3. **Track trends over time**: Monitor how metrics change as you iterate on your system.
4. **Combine multiple metrics**: Look at related metrics together for a more complete picture.
5. **Set thresholds**: Define acceptable ranges for critical metrics.
6. **Improve the metrics**: Use CLHF to continuously improve metrics.
