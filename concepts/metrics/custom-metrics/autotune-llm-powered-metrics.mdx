---
title: Improve LLM-Powered Metrics with Expert Feedback
description: Use Autotune to turn annotator and expert feedback into a structured tuning workflow that improves LLM-powered metric accuracy over time.
---

LLM-powered metrics are useful for evaluating quality at scale, but they do not always behave the way your team expects out of the box. When applied to a new domain they can produce false positives, false negatives, or results that miss important edge cases.

This usually happens because the metric prompt does not fully reflect your domain-specific standards, exceptions, or evaluation criteria. Teams often end up manually rewriting prompts, testing changes, and repeating that process until metric behavior improves.

Autotune solves this by turning expert feedback into a structured tuning workflow. Annotators and subject matter experts can review metric outputs, correct results, define expected values, and explain their reasoning in natural language. Galileo then aggregates that feedback, adapts the metric prompt, and shows how the prompt changed.

This makes it easier to improve metric quality over time and reach accuracy closer to what a human reviewer or data scientist would achieve after multiple rounds of prompt engineering.

## How it works

<Steps>
<Step title="Review metric results across logs">
Examine metric outputs across your logged spans, traces, or sessions to identify where the metric is underperforming.
</Step>
<Step title="Identify incorrect outputs">
Flag results that are incorrect or do not match your team's expectations.
</Step>
<Step title="Enter the expected value">
For each flagged result, enter the value the metric should have produced.
</Step>
<Step title="Add a natural-language explanation">
Describe why the corrected result is right. This reasoning is used by Autotune to understand the intent behind your feedback.
</Step>
<Step title="Retune the metric">
Run Autotune using the collected feedback. Galileo aggregates the feedback and adapts the metric prompt accordingly.
</Step>
<Step title="Review and test the updated prompt">
Inspect the changes to the prompt and test the updated metric before publishing.
</Step>
<Step title="Apply the improved metric to future runs">
Publish the updated metric so it is used for new logs and evaluations.
</Step>
<Step title="Optionally recompute historical results">
Recompute past results using the improved metric to backfill more accurate scores.
</Step>
</Steps>

## What Autotune supports

Autotune works across a broad range of metric and input configurations.

| Category | Supported |
| :--- | :--- |
| Metric types | Out-of-the-box and custom LLM-powered metrics |
| Output types | Categorical, percentage, boolean/binary, and other Galileo-supported output types |
| Input types | Spans, traces, and sessions |
| Feedback volume | Unlimited feedback per metric |

## How to create good feedback

Good feedback should clearly explain:

- What the metric got wrong
- What output it should have produced instead
- Why the corrected result is right

The most useful feedback is **specific**, **actionable**, **representative**, and **unambiguous**.

<Info>
Vague feedback like "this seems wrong" is less useful than "this should be `false` because the response contains a financial recommendation, which violates our compliance guidelines."
</Info>

## When to use Autotune

Autotune is most useful when:

- A metric is being applied to a new domain or use case
- Reviewers consistently disagree with metric outputs
- Domain-specific edge cases are not captured in the current prompt
- Manual prompt tuning is too slow or difficult to scale
- Your team wants a more systematic way to improve metric quality over time

Because it supports unlimited feedback, Autotune can continue improving as your team adds more examples and refines expectations.
