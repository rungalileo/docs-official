LLM-as-a-judge metrics evaluate quality of LLM applications at scale, but may not always reflect your team's domain-specific standards out of the box. Applied to a new domain, a metric can produce false positives, false negatives, or miss important edge cases — usually because the metric prompt doesn't fully capture your evaluation criteria.

Fixing this manually is time-consuming and hard to scale. Teams typically rewrite prompts, test changes, and repeat that cycle across multiple rounds with no guarantee the result matches what a domain expert would expect.

Autotune converts expert feedback into a structured tuning workflow. Annotators and subject matter experts review metric outputs, correct results, and explain their reasoning in natural language. Galileo aggregates that feedback, adapts the metric prompt, and shows exactly what changed.

## When to use Autotune

- A metric is being applied to a new domain or use case
- Reviewers consistently disagree with metric outputs
- Domain-specific edge cases aren't captured in the current prompt
- Manual prompt tuning is too slow to scale

## How it works

<Steps>
<Step title="Review metric results across logs">
Examine metric outputs across your logged spans, traces, or sessions to identify where the metric is underperforming.
</Step>
<Step title="Identify incorrect outputs">
Flag results that are incorrect or do not match your team's expectations.
</Step>
<Step title="Enter the expected value and explain why it's correct">
For each flagged result, enter the value the metric should have produced and add a natural-language explanation of why.
</Step>
<Step title="Retune the metric">
Run Autotune using the collected feedback. Galileo aggregates the feedback and adapts the metric prompt accordingly.
</Step>
<Step title="Review and test the updated prompt">
Inspect the changes to the prompt and test the updated metric before publishing.
</Step>
<Step title="Apply the improved metric to future runs">
Publish the updated metric so it is used for new logs and evaluations.
</Step>
</Steps>

<Note>
You can optionally recompute historical results with the updated metric after publishing.
</Note>

## How to provide good feedback

Autotune supports unlimited feedback per metric, so quality improves as your team adds examples and rationale. Good feedback should include:

- What output the metric should have produced
- Why the corrected result is right

Vague corrections like "this seems off" give insufficient signal to adapt the prompt.

## Which metrics are supported?

| Category | Supported |
| :--- | :--- |
| Metric types | Out-of-the-box and custom LLM-as-a-judge metrics |
| Output types | Boolean, categorical, percentage, count, and discrete |
| Metric levels | Spans, traces, and sessions |
