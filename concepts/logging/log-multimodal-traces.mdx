---
title: Log Multimodal Traces
description: Log images, audio, and documents alongside text in your traces
---

Modern AI applications go beyond text. A voice assistant processes audio. A document pipeline analyzes PDFs. An image moderation system evaluates visual content. Observing and debugging these applications requires traces that capture the full input context — not just text representations of it.

Galileo supports multimodal content in traces so you can:

- Inspect the exact image, audio clip, or document your model received
- Evaluate quality and behavior using multimodal metrics
- Debug failures with complete input context

---

## Choose a logging method

| Method | Use when... |
| :--- | :--- |
| **GalileoLogger — from a URL** | Your content is already hosted externally and accessible via URL |
| **GalileoLogger — from a local file** | You're working with files on disk and need to upload them directly |
| **LangChain handler** | Your app already uses LangChain — multimodal content converts automatically |

---

## Option 1: Log from a URL

Use `DataContentBlock` with the `url` field. No encoding required.

```python
from galileo.logger import GalileoLogger
from galileo.schema.content_blocks import TextContentBlock, DataContentBlock

logger = GalileoLogger()
logger.start_trace(
    input=[
        TextContentBlock(text="Describe this image"),
        DataContentBlock(modality="image", url="https://example.com/photo.png"),
    ],
    project="my-project",
)
logger.add_llm_span(
    input=[{"role": "user", "content": "Describe this image"}],
    output={"role": "assistant", "content": "It's a cat."},
    model="gpt-5",
)
logger.conclude(output="It's a cat.")
logger.flush()
```

## Option 2: Log from a local file

Encode local files as base64 and pass them with the `base64` and `mime_type` fields. This works for images, audio, and documents in a single trace:

```python
import base64
from pathlib import Path
from galileo.logger import GalileoLogger
from galileo.schema.content_blocks import TextContentBlock, DataContentBlock

image_b64_data = base64.b64encode(Path("photo.png").read_bytes()).decode()
audio_b64_data = base64.b64encode(Path("recording.wav").read_bytes()).decode()
pdf_b64_data   = base64.b64encode(Path("report.pdf").read_bytes()).decode()

logger = GalileoLogger()
logger.start_trace(
    input=[
        TextContentBlock(text="Analyze all of these files"),
        DataContentBlock(modality="image",    base64=image_b64_data, mime_type="image/png"),
        DataContentBlock(modality="audio",    base64=audio_b64_data, mime_type="audio/wav"),
        DataContentBlock(modality="document", base64=pdf_b64_data,   mime_type="application/pdf"),
    ],
    project="my-project",
)
logger.add_llm_span(
    input=[{"role": "user", "content": "Analyze all of these files"}],
    output={
        "role": "assistant",
        "content": "The image shows a cat, the audio is a piano note, and the PDF is a quarterly report.",
    },
    model="gpt-5",
)
logger.conclude(
    output="The image shows a cat, the audio is a piano note, and the PDF is a quarterly report."
)
logger.flush()
```

`DataContentBlock` supports three modalities: `image`, `audio`, and `document`.

## Option 3: Log with the LangChain handler

The LangChain handler converts multimodal message content to structured content blocks automatically. Pass multimodal messages the same way you normally would with LangChain — no extra setup:

```python
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage
from galileo.handlers.langchain import GalileoCallback

callback = GalileoCallback()
llm = ChatOpenAI(model="gpt-5", callbacks=[callback])

response = llm.invoke([
    HumanMessage(content=[
        {"type": "text",      "text": "What's in this image?"},
        {"type": "image_url", "image_url": {"url": "https://example.com/photo.png"}},
    ])
])
```

Supported content types: `text`, `image_url`, `audio_url`, `document_url`, `input_image`, `input_audio`. Base64 data URIs are supported — the handler extracts the payload and mime type automatically.

## View multimodal content in your traces

Multimodal content renders inline in the Log stream alongside span inputs and outputs:

- **Audio** renders as an inline waveform player you can play back directly, with download support
- **Images** display inline and can be downloaded
- **PDFs** appear as inline previews and can be downloaded

## Evaluate multimodal traces

Galileo provides out-of-the-box multimodal LLM-as-a-judge metrics and custom metric configuration for spans, traces, and sessions that contain multimodal content.

### Out-of-the-box metrics

Enable these directly on your Log stream — no configuration required:

| Metric | Modality | What it evaluates |
| :--- | :--- | :--- |
| **Visual Quality** | Image / PDF | Whether input quality is sufficient for the task to be reliably performed |
| **Visual Fidelity** | Image / PDF | Whether a generated image complies with brand rules, based on visible evidence |
| **Interruption Detection** | Audio | Turn-taking violations — agent overlap, premature barge-in, and user barge-in |

[See all preset multimodal metrics →](/concepts/metrics/multimodal-quality/multimodal-quality-overview)

### Custom LLM-as-a-judge metrics

1. Go to **Metrics** and create a new custom LLM metric.
2. Under capabilities, select **Image/PDF** or **Audio**.
3. Configure a model integration. See [recommended models](#recommended-models) below.
4. For Vertex AI, configure a separate GCP bucket and credentials for file uploads. See [how to set up a Vertex AI integration](https://v2galileo.mintlify.app/api-reference/integrations/create-or-update-vertex-ai-integration#create-or-update-vertex-ai-integration).
5. Enable the metric on your Log stream **before** logging content.

<Note>
Metrics compute only when the trace contains at least one attachment matching the enabled capability. A metric with **Image/PDF** enabled returns N/A if the trace contains only audio, or no attachments at all. Similarly, a metric with **Audio** enabled returns N/A on image-only traces.
</Note>

## Reference

### Supported formats

| Modality | Formats |
| :--- | :--- |
| Image | `png`, `jpeg` |
| Audio | `mp3`, `wav` |
| Document | `pdf` |

### Recommended models

For best results, use GPT-5 or later (OpenAI) for image and PDF evaluation, and Gemini 3+ via Vertex AI for audio.

---

## Known limitations

- **API readback returns content blocks as JSON strings.** `List[ContentBlock]` values are returned as JSON-stringified strings rather than native list objects. The data is complete and parseable.
- **LangChain handler stores the full message list.** Trace input/output contains the full serialized message structure (e.g., `[{"content": [...blocks...], "role": "user"}]`), not bare content blocks.
- **Recompute is not supported for multimodal metrics.**
- **Multimodal metrics are not supported in playground or prompt experiments.**
